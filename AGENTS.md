# Fiken Printed CLI Agent Guide

This directory is a generated `fiken-cli` printed CLI. It was produced by [CLI Printing Press](https://github.com/mvanhorn/cli-printing-press), so treat systemic fixes as upstream Printing Press fixes first. Keep local edits narrow and document why a generated-tree patch belongs here.

## Local Operating Contract

Start by asking the generated CLI for current runtime truth:

```bash
fiken-cli doctor --json
fiken-cli agent-context --pretty
```

Use runtime discovery instead of relying on a copied command list:

```bash
fiken-cli which "<capability>" --json
fiken-cli <command> --help
```

Add `--agent` to command invocations for JSON, compact output, non-interactive defaults, no color, and confirmation-safe scripting:

```bash
fiken-cli <command> --agent
```

Before running an unfamiliar command that may mutate remote state, inspect its help and prefer a dry run:

```bash
fiken-cli <command> --help
fiken-cli <command> --dry-run --agent
```

Use `--yes --no-input` only after the target, arguments, and side effects are clear.

For install, auth, examples, and longer product guidance, read `README.md` and `SKILL.md`. This file intentionally stays small so repo-local agents get invariant local guidance without duplicating the generated docs.

## Release Ledger

`CHANGELOG.md` and `.printing-press-release.json` are the public library's per-CLI release ledger. Fresh prints may carry blank skeletons, but the final `YYYY.M.N` CLI release version is assigned only after a publish PR merges in `mvanhorn/printing-press-library`. Do not hand-bump those files or edit `var version = ...` for release bookkeeping; preserve existing ledger files on reprint and let the library workflow stamp the next release.

## Local Customizations

This directory is **generated output** -- a fresh print can overwrite the whole tree, so ad-hoc hand-edits don't survive on their own. If you modify the generated code, record each change under `.printing-press-patches/` (parallel to `.printing-press.json`) so a regen carries the intent forward instead of silently dropping it.

The entry shape, and the altitude to write it at -- a durable reprint-guard, not a changelog -- live in the source catalog's `AGENTS.md`, which is the single source of truth; this guide intentionally doesn't duplicate them.

## Regeneration policy

**fiken-cli is never regenerated in place.** The hand-authored detector layer, the mirror
fixes and the OAuth patches do not survive a reprint on any path. If a regeneration is
ever wanted, the only safe sequence is: print into a fresh scratch tree, run
`scripts/harmonize.sh` over it, run a `regen-merge` **dry run**, and land a hand-reviewed
diff. Never `--force`, never `lock promote` over this tree.

Every edit to a `Generated by CLI Printing Press ... DO NOT EDIT` file needs a
`.printing-press-patches/<id>.json` record with `files[]` and `call_sites[]` — the
validator reads only `*.json`, so a `.md` note protects nothing. The schema is in
`../skills/reference/patch-records.md`. Prefer a new hand-authored file over editing a
generated one; where a generated file must change, keep the diff minimal and record it.

`make check` enforces this: every `.go` file under `internal/` and `cmd/` carries exactly
one of the generator header or a `HAND-AUTHORED` comment, every patch record's call sites
still exist, and no patch note lacks its `.json` sibling.

**Test company.** Only `agensia` may be written to. Every write-path and mirror test runs
against it. Live mode is switched by an untracked env file (`.env.local` or
`~/.config/fiken-cli/env` setting `FIKEN_MODE`), never a CLI flag; the guard that enforces
it is `internal/client/write_guard.go` (see it once Phase 1 lands) plus the transport in
`internal/client/fiken_transport.go`. A binary that has not wired the guard's resolver
denies every mutating request.
